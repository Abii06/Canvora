# Contributing to Canvora 🎨✨

Thank you for your interest in contributing to **Canvora**! This project is participating in the **GirlScript Summer of Code (GSSoC)**. We welcome contributions from developers of all skill levels.

To maintain a healthy, productive, and respectful community, please follow these guidelines.

---

## 🚀 How to Get Started

1. **Fork the Repository**: Click the "Fork" button at the top right of this page to create your copy of the repository.
2. **Clone the Repository**: Clone your fork to your local machine:
   ```bash
   git clone https://github.com/YOUR_USERNAME/Canvora.git
   cd Canvora
   ```
3. **Setup and Run Locally**: Follow the step-by-step setup guide in the [README.md](README.md) to install dependencies and run the frontend and backend servers.

---

## 🎯 Issue Assignment Guidelines (GSSoC)

To ensure a fair and organized contribution process:

* **Find an Issue**: Browse the open issues in the **Issues** tab. Look for issues labeled with `gssoc` and difficulty tags (`level1`, `level2`, `level3`).
* **Request Assignment**: Comment on the issue asking to be assigned.
  * *Example:* "I would like to work on this issue under GSSoC. Please assign it to me."
  * *Tip:* Briefly outline your approach to solving the issue in your comment. This helps project maintainers assign it to you faster.
* **Wait for Assignment**: Do not start working on an issue or open a Pull Request until a Project Admin or Mentor officially assigns the issue to you on GitHub.
* **Timeline**: Once assigned, you have **3 days** to submit a draft PR or provide an update. If there is no progress or communication within 3 days, the issue will be unassigned and opened for other contributors.

---

## 🛠️ Pull Request (PR) Guidelines

When you are ready to submit your changes, follow these rules:

1. **Create a Branch**: Create a descriptive branch for your work:
   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b bugfix/your-bug-name
   ```
2. **Link the PR to the Issue**: In your Pull Request description, explicitly link the PR to the issue you were assigned using GitHub keywords.
   * *Example:* `Closes #12` or `Fixes #34`.
   * **Note:** PRs that are not linked to an assigned issue will not be reviewed or merged, and will not count towards GSSoC points.
3. **Code Style & Quality**:
   * Follow the project tech stack: React, Tailwind CSS, Express, and MongoDB.
   * Write clean, documented, and reusable code.
   * Ensure there are no console logs or debugging comments left in the final code.
4. **Submit for Review**: 
   * Push your branch to your fork and open a Pull Request against the `main` branch of the original repository.
   * Fill out the PR template completely.
   * Wait for review from the Project Admins/Mentors. Be ready to make suggested changes if requested!

---

## 🏷️ GSSoC Labels & Leaderboard Points

Contributions are evaluated based on difficulty levels:

* 🟢 **Level 1 (Easy / Beginner)**: Points allocated for documentation, simple styling, bug fixes, or minor enhancements.
* 🟡 **Level 2 (Medium / Intermediate)**: Points allocated for structural frontend work, creating new components, API routes, or form validation.
* 🔴 **Level 3 (Hard / Advanced)**: Points allocated for complex database logic, backend security, integrations, or major features.

Once your PR is reviewed and accepted, the project admins will apply the `gssoc:approved` tag along with the appropriate `level` tag to ensure your points are tracked on the GSSoC Leaderboard.
